# 2.13.5: Loaded Object Polling

Full Fabric / Paper Client **2.13.5**, Paper Server **0.14.6**, for **Minecraft 26.3 / Java 25**.

## Changes

- Reuse a cached list of loaded ENB object keys until its membership changes. Chunk/world unload, reload and registration invalidate the cache; object types are still read from the current ledger.
- Avoid an extra cached-coordinate lookup for stable notes, transmitters and projections. Receivers retain their required world lookup, and changed/deleted objects retain their correct broadcast coordinates.
- Preserve one-tick redstone polling, independent projection timing, wireless power, all note parameters and saved data, Litematica metadata, CraftEngine registration, optional listener audio and player preferences.
- Add regression coverage for cache invalidation, repeated registration, type changes and render packet coordinates. Client features, language behavior and audio content are unchanged.

| `ExtendedNoteBlock-Full-Fabric-2.13.5-mc26.3.jar` | Single-player or Fabric server/client |

| `ExtendedNoteBlock-CraftEngine-2.13.5-mc26.3.zip` | ENB registration resources for CraftEngine on the server |

**CraftEngine 26.9.2 is required for Paper Server.** The ZIP contains ENB registration resources, not the CraftEngine plugin. Fabric uses Loader **0.20.1** and Fabric API **0.165.0+26.3**. Automatic Litematica transfer optionally uses Litematica **0.29.1** and MaLiLib **0.30.2**. Install only one of Full Fabric and Paper Client.

## Upgrade

Stop the server normally and back up the ENB and CraftEngine data directories. Replace the old ENB plugin JAR while retaining music, projections, configuration, optional-audio files and `optional-audio-players.txt`. No saved-data migration is required. Existing 2.13.3/2.13.4 CraftEngine registration resources remain compatible; new installations can use the ZIP above.

CraftEngine generates and hosts the complete resource pack; ENB sends it and tracks loading. Preserve existing pack hosting and split-audio settings. See the [installation guide](../INSTALLATION.md). No separate `Server-Resources` download is needed.

## Validation and limits

The local sandbox checks cover 83 Java tests and 34 Python checks. Isolated replay comparisons use 0, 128 and 8,879 loaded objects, three independent JVMs per scenario and identical data, dependencies, JVM settings and measurement core. Full-load checks also exercise the original coordinate resolver against a fixed mock block. See the [performance notes](../PERFORMANCE.md) for methodology and limits.

Mock replay results measure bridge polling, not live-server TPS/MSPT or client FPS. Real CraftEngine calls, physical world access, music playback and chunk-churn array allocation require separate measurement. This release does not update any running server automatically.
