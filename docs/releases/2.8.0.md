# ExtendedNoteBlock 2.8.0 — Minecraft 26.2

## Paper Client parity and core fixes

- Rebuilt the Paper-managed Extended Note Block editor to mirror the Full Fabric editor: General MIDI instrument combo box, velocity/sustain/delay controls, fade controls, and the same horizontally scrollable 128-note piano keyboard with octave labels.
- Added a registry-safe SoundEngine mixin to restore Full Fabric's pitch path in Paper Client. ExtendedNoteBlock sounds bypass Minecraft's vanilla final-pitch clamp to address low MIDI notes collapsing to the same pitch. Actual multi-octave behavior still requires in-game listening verification.
- Fixed Paper Client NBS Projection `.litematic` exports resolving ExtendedNoteBlock positions to air. Paper Client now exports vanilla-safe carriers (`minecraft:note_block`, red concrete, purple concrete) while Full Fabric continues to export real `extendednoteblock:*` blocks.
- Paper-safe Litematic files retain an `ExtendedNoteBlockBridge` root metadata tag containing note coordinates, MIDI note, GM instrument, velocity, sustain, delay and pitch-cents data for future bridge restoration/import workflows.
- Paper Client continues to pass the registry-safety scan and does not include Full Fabric custom block/item registration classes.

Paper Server protocol is unchanged in this release and remains version 0.8.1.

## Validation and remaining limits

[Release CI run 33939054241](https://github.com/GoldenEggOVO/ExtendedNoteBlock/actions/runs/33939054241) passed its build and static packaging checks. This does not replace gameplay verification on Paper / Purpur.

Paper-safe Litematic exports retain the carrier blocks and bridge metadata, but automatic ENB registration / parameter restoration after Litematica paste or Easy Place is not implemented in 2.8.0. Receiver upload and the remaining Paper GUI work are tracked in the [roadmap](../ROADMAP.md).
